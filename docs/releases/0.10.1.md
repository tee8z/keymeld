# Keymeld 0.10.1

Enclaves retain command identifiers and payload digests for replay checks instead
of retaining completed command payloads. Large signing requests no longer remain
in session history after processing. Replay and authorization checks are unchanged.

The SDK sends each signing round to its enclaves concurrently. It saves all exact
requests before transmission, waits for all peers, and records authenticated
responses before returning a peer error. Retries retain the original requests
and nonce identities, including when a response is lost after execution.

During final aggregation, the coordinator enclave keeps the coordinator's signing
rounds and drops redundant local copies. Every participant's partial signature is
still verified against the round used to produce the final signature. Local
partial signatures are returned before any copies are dropped.

Custom enclaves must rebuild against this release to receive the fix. Updating
the gateway alone does not replace a custom Coordinator enclave.

Validation: enclave unit and KMS integration tests, Clippy, and the release
end-to-end suite. The memory regression submits 96 MiB of command payloads and
checks that retained command metadata remains below 4 KiB.
Signing regressions cover concurrent rounds, failed checkpoints, lost responses,
unchanged retry identities, and corrupted ordinary and adaptor partial signatures.
