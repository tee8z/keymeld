# Keymeld 0.10.2

Escrow trial transitions share immutable preparations, executions, signing permits, bindings, and receipt payloads.
Validating a new operation no longer copies every previously retained payload.
The candidate state replaces live state only after all checks pass.
Sealed receipt formats, authorization checks, and recovery behavior remain unchanged.

Enclaves log confidential reply-cache bytes and escrow state counts once per minute.
Escrow diagnostics include response-cache accounting, preparation and execution counts, receipt payload bytes, and signing permits.
Response accounting includes the existing per-entry overhead estimate; it is not total heap usage.
A busy state is counted as unavailable instead of blocking protocol work.
These counters do not impose an aggregate enclave memory limit.

The SDK exposes opaque runtime revisions for unchanged journal entries.
Applications can reuse a committed entry’s encoding while its revision matches.
Clones preserve revisions; deserialization and outcome changes create new revisions.
The serialized journal format is unchanged.

Custom enclaves must rebuild against this revision to receive the memory changes.
The Coordinator verifier enclave requires its own release and deployment.
Validation covers shared receipt storage, isolated trial updates, busy-state diagnostics, SDK revisions, and existing escrow recovery regressions.
