# Keymeld 0.10.3

SDK journal clones share immutable command and signing-batch payloads.
Recording or clearing an outcome copies only the changed entry.
Existing journal JSON, runtime revisions, checkpoint ordering, and retry identities remain compatible.

Each enclave reserves preparation-reply capacity before admission and retains a charge while its reply remains cached.
All sessions share a 256 MiB preparation-reply budget, including pending reservations.
Exact cached retries and authorized execution or recovery remain available when that budget is exhausted.
Rejected preparations use the existing authenticated preparation-exhausted response and can retry after capacity returns.

At 75 percent budget use, periodic cleanup reduces idle keygen retention to five minutes.
Busy and recently used sessions remain protected by the existing cleanup gates.
Clients restore released sessions through their durable journals and sealed receipts.
The normal configured retention applies again when pressure clears.
Enclaves log reserved bytes, the budget, and admission refusals once per minute.

The budget covers cached preparation replies and their reservations, with estimated per-entry overhead.
It does not cap execution receipts, native cryptographic allocations, request decoding, or total process memory.
Custom verifier enclaves must rebuild against this revision to receive these changes.

Validation covers shared journal isolation and JSON compatibility, concurrent budget admission, exact retries, execution under exhaustion, and signing after pressure-driven cleanup.
