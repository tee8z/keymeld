# Keymeld 0.10.4

When the enclave-wide preparation-reply budget is full, preparation is refused with the new authenticated `EscrowPreparationBusy` response instead of `EscrowPreparationExhausted`.
The SDK maps it to the retryable `SdkError::EscrowPreparationBusy`.
`EscrowPreparationExhausted` keeps its meaning: a permission or session has no preparations left.
Clients that treat exhaustion as final no longer retire work because other sessions temporarily filled the shared budget.
serde's `rc` feature is enabled only in the SDK, which serializes shared journal entries.

Exact-retry digests are computed only for the commands they protect: signing rounds and keygen session starts.
They are computed before a session's state is locked.
Escrow and other commands keep an ID-only history entry, so an exact replay of an applied participant batch is still recognised after its cached reply is evicted.
Signing commands are recorded once per round instead of twice.
Escrow trial state is committed field by field, so a field a later change adds cannot be silently dropped.

The SDK's checkpoint revision contract is now checked across real signing rounds, lost responses, rejected-command resets, and keygen restoration.

Custom verifier enclaves must rebuild against this revision to report the busy response.
