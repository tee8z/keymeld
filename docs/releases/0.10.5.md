# Keymeld 0.10.5

Preparation-reply budget pressure now counts retained replies only.
Pending admission reservations no longer switch idle keygen sessions to the shortened retention, so the exact-retry window for a lost reply stays at the configured length until cached replies actually fill the budget.
The pressure threshold and the shortened retention are named where they are defined.

When a preparation executes, its cached Prepare reply is replaced by a marker that holds the executed preparation, and the reply's budget charge returns.
An exact retry of that Prepare is answered with the same preparation sealed again under its original request context; the verifier is never called again, so a retry cannot produce a different action.
Bind replies stay cached until the session is released, because one binding serves every permission of its participant.

Retained escrow state shares one copy of each executed preparation, its signing scope and its binding across the preparation, execution, permit and binding maps, and the Execute retry path reuses the stored receipt.
Sealed state bytes and digests are unchanged.
The escrow memory report adds prepared, scope and binding byte estimates, counting a shared value once.

Tests cover reservation release on cancellation and verifier refusal, charge release when sessions are released, retries of executed preparations, shared allocations, and byte-identical sealing.
A reply's worst-case size is checked against its reservation at compile time.

Custom verifier enclaves must rebuild against this revision to receive these changes.
