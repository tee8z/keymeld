# KeyMeld 0.4.1 (beta)

This patch updates the SDK and examples to the published `dlctix` 0.1.0 package.
It includes the authorization and security fixes from [0.4.0](https://github.com/tee8z/keymeld/releases/tag/v0.4.0).

## Changes

- Resolve `dlctix` from crates.io instead of the removed `external-signing-api` branch.
- Reject attestation signing batches with missing adaptor points. Such batches previously fell back to plain signatures.
- Verify the complete signature set before the DLC example creates a signed contract.
- Test MuSig2 signature compatibility, invalid signature rejection, and missing or infinite adaptor points.
- Include the `dlctix` feature in CI and release WebAssembly builds.

## Upgrade

Resolve direct `dlctix` dependencies from crates.io to share the SDK's types:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.4.1", features = ["client", "dlctix"] }
dlctix = "0.1.0"
```

`dlctix` 0.1.0 rejects duplicate signer public keys and adds other contract validation checks.
Use a fresh signing key for each ticket entry.
See the [dlctix release notes](https://github.com/tee8z/dlctix/releases/tag/v0.1.0) for the complete validation changes.

For upgrades from versions through 0.3.5, follow the [0.4.0 migration instructions](https://github.com/tee8z/keymeld/blob/v0.4.0/docs/releases/0.4.0.md#upgrade).

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
