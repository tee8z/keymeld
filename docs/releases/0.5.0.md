# KeyMeld 0.5.0 (beta)

This release adds generic, participant-authorized escrow and a confidential signing transport alongside the existing MuSig2 service.
It also moves the workspace to `musig2` 0.4.
It includes the fixes from [0.4.1](https://github.com/tee8z/keymeld/releases/tag/v0.4.1).

## Changes

- Add a confidential transport (`/api/v1/confidential`). Policies, participant rosters, signing messages, evidence, results, and private errors travel encrypted to the intended attested enclave; the gateway relays routing metadata and ciphertext only.
- Add a generic escrow engine to the enclave. Each signed policy grants signing, named-secret release, or signing-key release independently, and application rules live in statically registered verifiers in a measured enclave image.
- Add `ConfidentialSession` to the SDK with an application-owned durable journal. Bind and prepare are replayable; execute is single-use.
- Keep the gateway-orchestrated keygen and signing API as a first-class peer of the confidential path. A confidential session rejects the orchestrated command paths.
- Keep the MuSig2 rounds client-mediated so a signer whose key lives outside the enclaves can still be merged into the nonce and partial-signature sets.
- Raise the size limits: payload 2 MiB, escrow wire 4 MiB, preparation cache 64 MiB, confidential plaintext 8 MiB. Batches still cannot be split across requests ([#58](https://github.com/tee8z/keymeld/issues/58)).
- Enable the `escrow` feature by default in `keymeld-enclave` and `keymeld-gateway`. `test-support` stays opt-in and must not be enabled in production images.
- Move the workspace to `musig2` 0.4 so every crate links one copy of `musig2` and `secp`.
- Fix `restore_keygen` treating a first run as a failed restart, and fix key distribution rejecting its own success outcome with two or more enclaves.
- Re-export `EnclaveRecipientAuthorization`, `ParticipantRegistrationData`, `EnclaveBatchItem`, and `EnclaveBatchResult` from the SDK, and add a `From` conversion for `SubsetDefinition`.
- Scope the patched OpenSSL to Keymeld builds so the Nix closure no longer rebuilds unrelated packages.

## Upgrade

Point at the new tag and enable the client features you use:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.5.0", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.5.0" }
dlctix = "0.1.0"
```

No public item, gateway route, or Cargo feature was removed.
`RegistrationEnvelope` gains an optional `escrow` field, and the protocol enums gain escrow and confidential variants.
Code that builds `RegistrationEnvelope` by struct literal or matches those enums exhaustively needs a one-line update.

`musig2` 0.4 changes `FirstRound::new` to return `RoundSetupError`, and `SecNonce` now embeds the signer's public key.
Public nonces are unchanged and no stored data needs migrating.

For upgrades from versions through 0.3.5, follow the [0.4.0 migration instructions](https://github.com/tee8z/keymeld/blob/v0.4.0/docs/releases/0.4.0.md#upgrade).

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
