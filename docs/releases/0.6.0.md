# KeyMeld 0.6.0 (beta)

This release adds plain BIP340 signing to the escrow engine, lets a verifier authorize it before keygen completes, and lets a session serve those permissions for a partial roster.

## Changes

- Add `Action::SignBip340` and `Permission::SignBip340`: sign 32-byte digests, such as taproot script-path sighashes, with the participant's own untweaked key. The scope must name that key, a BIP340 attempt never targets a MuSig2 signing session, and a verifier rule computes every digest from the transaction it authorizes. Signatures come back as `ExecutionOutput::Bip340Signatures`.
- Add `Repetition::VerifierAuthorizedAttempts`: each fresh attempt may prepare and execute once with its own messages, for spends retried with new inputs. It applies to verifier-authorized `SignBip340` and `Sign`, and is refused for releases and exact scopes.
- Add unbound grants. A verifier authorizes each action from the participant's own registered policy alone, without a completed keygen or roster. They are allowed only for verifier-authorized BIP340 signing; the enclave derives their binding instead of unsealing a receipt, and a request for one carries no binding receipt.
- Add `ConfidentialSession::register_partial_roster`, which registers only the participants who are present, within the signed manifest, and never builds an aggregate key. Those participants' unbound permissions then work without `complete_keygen`. A registered partial roster can't change; repeats replay the journaled requests exactly.
- A session whose participants are still registering serves unbound prepare and execute, and nothing else.
- Fix an escrow command reaching a registering session failing it, and a refused registration batch discarding the session's registrations.

## Upgrade

Point at the new tag:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.6.0", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.6.0" }
```

No public item, gateway route, or Cargo feature was removed.
`Action`, `Permission`, `Repetition` and `ExecutionOutput` gain variants, so code that matches them exhaustively needs a one-line update.
`complete_keygen`, `restore_keygen`, bound permissions, releases, exact scopes and MuSig2 signing behave as in 0.5.0.

The enclave changes in this release, so rebuild enclave images from this tag; on Nitro that changes their measurements.
A 0.5.0 enclave fails a registering session on its first escrow command.

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
