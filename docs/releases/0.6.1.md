# KeyMeld 0.6.1 (beta)

This release takes the September dependency updates and makes releases faster to build. No public API changes.

## Changes

- Update dependencies, including breaking releases:
  - aes-gcm 0.11
  - x509-cert 0.3
  - rcgen 0.14
  - coset 0.4
  - base64 0.23
  - aws-nitro-enclaves-nsm-api 0.5
  - bdk_wallet 2.4
  - 23 minor and patch updates
- Nonces and keys for session encryption now come from `rand::rngs::OsRng`, and aes-gcm is built with only `aes` and `alloc`. This keeps the WASM SDK building without another getrandom backend. Decryption still refuses a nonce of the wrong length, with the same error.
- The Nix toolchain moves from Rust 1.88.0 to 1.92.0, which the NSM API 0.5 requires.
- Releases build in about 5 minutes instead of about 36.
  - A tag reuses the enclave images built on master. They are the same derivations, so their measurements match a build from source.
  - Gateway images are assembled from the release's own binaries.

## Upgrade

Point at the new tag:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.6.1", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.6.1" }
```

No public item, gateway route, or Cargo feature changed. `keymeld-enclave` now needs Rust 1.92 or later, so crates that depend on it do too.

The enclave's dependencies change in this release, so rebuild enclave images from this tag. On Nitro that changes their measurements: update any pinned PCRs before routing sessions to the new images.

Not included yet:
- secp256k1 0.33: this waits for a musig2 release built on it.
- spki 0.8: this waits for `cms` 0.3.

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
