# KeyMeld 0.7.1 (beta)

This release fixes the gateway's enclave connection pools, which grew by about one connection per enclave every hour and reported an idle gateway as overloaded. No public API changes.

## Changes

- The gateway cleans up each enclave's connection pool every minute. Before, nothing ran the cleanup, so a connection past its one-hour lifetime stopped taking requests but stayed in the pool, and the pool opened another.
- Per-minute request counts expire with their minute. An idle connection no longer looks loaded, so `keymeld_enclave_connection_avg_load`, `keymeld_enclave_connection_load_percent` and the requests-per-minute metrics reflect current traffic, and the "connections overloaded" warning stops.
- When a connection's read or write task ends, the other is stopped, on both the gateway and the enclave side. The pool removes connections that have closed and no longer selects them.
- A connection closed after the read timeout with no requests is logged at debug level instead of as an error.

## Upgrade

Point at the new tag:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.7.1", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.7.1" }
```

No public item, gateway route, message layout or Cargo feature changed. The gateway and enclaves can be upgraded independently, and 0.7.0 enclaves work with a 0.7.1 gateway. Persisted state needs no migration.

`keymeld-core` changes in this release, so rebuild enclave images from this tag to pick up the enclave-side fixes. On Nitro that changes their measurements: update any pinned PCRs before routing sessions to the new images.

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
