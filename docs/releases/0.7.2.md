# KeyMeld 0.7.2 (beta)

This release stops the gateway reporting an idle enclave connection as overloaded, and takes the late-September dependency updates. No public API changes.

## Changes

- A connection's load is now the requests sent on it and not yet answered. Before, it was the requests in the current minute, so the gateway's own health checks made a single idle connection look overloaded: the pool considered opening another connection, and the gateway logged "connections overloaded" every minute. `keymeld_enclave_connection_avg_load` and `keymeld_enclave_connection_load_percent` now measure requests in flight, as their descriptions already said; per-minute counts still feed the request-rate metrics.
- Dependency updates:
  - utoipa 6 with utoipa-scalar 0.4;
  - tower-http 0.7.1;
  - rand 0.10. secp256k1 and musig2 still take rand 0.9 generators, so key generation uses the generator secp256k1 re-exports. The WASM builds enable getrandom's `wasm_js`.
- The API documentation UI test checks that the page returns and embeds the OpenAPI spec, instead of waiting on Scalar's CDN.

Not included yet: der 0.8, which waits for `cms` 0.3 and `pkcs1` 0.8.

## Upgrade

Point at the new tag:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.7.2", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.7.2" }
```

No public item, gateway route, message layout or Cargo feature changed. The gateway and enclaves can be upgraded independently. Persisted state needs no migration.

The enclave's dependencies change in this release, so rebuild enclave images from this tag. On Nitro that changes their measurements: update any pinned PCRs before routing sessions to the new images.

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
