# KeyMeld 0.8.0 (beta)

This release shrinks the escrow state the enclave seals and hands back to callers by about 20 times. No public API changes; the version steps because a rollback to 0.7.x needs care (see Upgrade).

## Changes

- The enclave deflates a sealed escrow state before encrypting it, under a new sealing label (`escrow_state_v2`). A contract signing scope repeats every signer's key as a JSON integer array, so for a large pool each prepared receipt was about 1 MB on the wire, and every Execute request echoed it back. Sealed for a 22-signer scope, the state goes from about 318 KB to about 14 KB, and the Execute request from about 1.1 MB to about 53 KB.
- Unsealing decrypts under the enclave's sealing key first and inflates only then, with the decompressed size bounded by the escrow payload limit. States sealed by 0.7.x (`escrow_state_v1`) still unseal.
- The gateway does not change: it relays the sealed state as before and never sees its contents.
- New enclave tests cover the round trip, a v1 state, a tampered state, an oversized stream and the size of realistic 22- and 25-signer scopes.

## Upgrade

Point at the new tag:

```toml
keymeld-sdk = { git = "https://github.com/tee8z/keymeld", tag = "v0.8.0", features = ["client", "dlctix"] }
keymeld-core = { git = "https://github.com/tee8z/keymeld", tag = "v0.8.0" }
```

No public item, gateway route, message layout or Cargo feature changed. Rebuild enclave images from this tag; on Nitro that changes their measurements, so update any pinned PCRs before routing sessions to the new images. The gateway can stay on 0.7.2.

Rolling back: a 0.7.x enclave cannot unseal states this release sealed, so escrows prepared under 0.8.0 and still in flight would have to be prepared again after a rollback. Finished escrows are unaffected.

## Beta status

This release retains the 0.4.0 beta limitations.
Validation uses simulated TCP enclaves and a mock KMS.
Real AWS Nitro hardware acceptance remains incomplete; use test keys and test funds only.
