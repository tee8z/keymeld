# KeyMeld v0.9.0

Escrow signing batches can hold up to 1,536 items, enough for a 20-player pool that pays two places (1,182 items) with retry headroom.
The escrow payload limit rises to 8 MiB, the escrow wire bound to 16 MiB, the preparation cache to 128 MiB, and confidential plaintext to 16 MiB.
The vsock frame default follows the confidential wire size, and the gateway raises a smaller configured value to it.
Vsock waits rise to 900 s, verifier prepare and execute timeouts to 300 s, and the SDK's confidential request timeout to at least 960 s.
An oversized response frame now closes the connection instead of being parsed as the next frame.

This changes the wire limits between the gateway and the enclaves.
Release and deploy the gateway, the Keymeld enclaves and the coordinator's verifier enclave together; an older peer refuses the larger messages.
Deployments that set `vsock_timeout_secs` or `network_read_timeout_secs` to 300 explicitly should raise them to 900.
Applications embedding the enclave must update their Keymeld source pin and rebuild.
Preserve sealed key material and durable confidential journals; the sealed-state format is unchanged.
